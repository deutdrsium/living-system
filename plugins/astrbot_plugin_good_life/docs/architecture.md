# 技术说明

插件标识为 `astrbot_plugin_good_life`，核心包为 `good_life`。第一阶段依赖配套版本的「我会永远陪着你」，通过进程内 `companion.life.v1` 契约连接，不向新插件交出主插件数据库连接或完整应用对象。

生活插件持有独立 SQLite 数据库与唯一生活调度器，管理日程、阅读、浏览、睡眠、既有角色状态及对应配置。旧执行器在归属迁移后停用，生活插件缺失或连接中断时不会自动恢复旧执行器。主插件仍负责身份、授权、来源、平台连接、消息发送、通用模型调用和任务审计；状态维护使用主插件的受监督模型任务，生活插件负责调度、状态计算、提示词和数据。

跨库写入保留原操作编号、授权与来源检查；生活库先准备变更，主插件保存决定及审计，双方确认后对外可见。活动完成等事件持久化，主插件按事件编号接收并去重，供日记、梦境、兴趣和晨间换装使用。插件重载会撤销旧绑定，重新握手后恢复；结果不明的原模型或平台操作不因迁移自动重试。

插件数据位于 AstrBot 的 `plugin_data/astrbot_plugin_good_life`。书籍原文和通用来源资产继续由主插件管理；日程、生活活动、阅读进度、浏览记录、状态、配置和相关去重记录由生活插件保存。管理 API 复用主插件的 Dashboard 身份、角色和权限检查；日记、梦境和社交账号仍在原插件管理。

迁移和回退工具位于配套仓库的 `tools/`。正式切换须先停止 AstrBot，制作同一停写时点的运行库与配置库备份，运行 `prepare_life_cutover.py`，再安装两个配套插件和三个配套数据库。`deploy_life_cutover.py` 在服务器上完成一次停写、备份、候选生成和安装，并在新执行器启动前出错时恢复原服务。若新插件已产生数据，必须先停写并通过 `prepare_life_rollback.py` 回迁生活数据、配置和去重记录，不能直接覆盖旧快照。切换记录和校验清单应单独保存，数据库、账号、书籍和备份不进入 Git。

本阶段保留原有状态及睡眠规则，不实现未来的统一状态变量、触发器和可插拔任务内核。原插件及迁出代码由 menglimi 创作，遵循 AGPL-3.0-only。
