# 生活服务接口（开发中）

主插件以 `companion.life.v1` 提供进程内注册入口；新插件当前注册 `calendar_read`、`calendar_command`、`configuration_read`、`configuration_command`、`activity_read`、`activity_control`、`activity_history`、`browsing_read`、`browsing_command`、`state_read`、`state_command`、`state_schedule` 十二个同步处理器。宿主已在开发版接入配置读取、写入和审计；线上归属尚未切换，契约尚未发布。

注册只接受 AstrBot 中唯一激活且目录标识为 `astrbot_plugin_good_life` 的插件实例。注销、停用或版本不兼容会撤销租约；进行中的回调结束前不允许替换提供方，避免两代执行器重叠。异步工作由新插件自己的调度器管理，回调本身不得返回 awaitable。

注册不授予角色访问权。主插件仍负责按原角色、会话、来源和版本核验权限，保留模型、平台与审计能力；接口不向新插件暴露主插件数据库或完整应用。日程、活动和状态可从同一已固定的生活快照读取；跨库写入须通过相应命令交接，不能嵌入宿主数据库事务。

日程批量交接在生活库内一次提交全部记录和回执，宿主先核验每项授权并暂缓受影响的提醒；宿主确认之前整批读取被阻挡。中断后使用原决议恢复，未决定的准备记录被撤销。自动、聊天手动规划和日程对话干预已在隔离宿主接入。

状态维护的周期、手动请求和私聊干预由新插件调度，宿主继续检查原授权并监督模型调用。干预请求携带对话输入版本与本次宿主运行标识；有新消息或宿主重启后，尚未开始的旧干预失效，不自动重放。未处理的请求会阻止回退演练。

手动入睡和唤醒的交接可由新调度器恢复：已决定提交的命令沿原决定完成，尚无宿主决定的准备记录撤销；不重新发起原操作。

阅读取消在生活库中一次写入取消版本和按原规则产生的后续片段；宿主确认后通知新调度器停止该片段的执行任务，再确认生活库回执。中断恢复保留同一操作和来源校验，不能跨会话替代原执行身份。

来源撤回和书籍删除由宿主持久撤回原文，生活库原子取消同一来源的未完成片段并停止对应工作；撤回保留记录，删除移除选中的记录。已提交决定可由新调度器恢复，宿主与生活库仍保留各自操作回执。

新插件入口已连接提供方、自动日程规划、睡眠、自动阅读、自动浏览及原有状态维护的周期触发；模型、平台连接和审计仍通过宿主的限权能力执行。浏览的内容回执由生活库保存，宿主的兴趣、反馈表只保留关联索引及原有互动操作回执；未决互动不会自动重复。启用依赖最终切换标记，候选生成工具的完成门禁目前关闭。日程采用宿主验证的迁移凭证，其他域的切换核验和完整执行器仍未完成。本文件描述开发代码与隔离测试，不表示生产已经启用。
