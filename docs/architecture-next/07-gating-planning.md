# 门控与规划选择

依赖：[生命周期](04-kernel-lifecycle.md)、[触发器](06-triggers-events.md)。规划与选择使用同一事实快照和资源接口，不能各维护一份忙闲状态。

## 门控分两次

廉价门控只用已有快照，过滤明显不可能项：模板依赖、身份/场景能力、当前忙碌、最低空闲、已知钱/精力底线、冷却。它不为全部候选调用地图或 LLM。

入选候选 prepare 获取必要路线、材料、价格和耗时；最终门控重新检查版本、权限、完整时间窗与资源。若失败，记录原因，本轮有界地转看其他候选或保持空闲。不能把失败候选反复选中、报价、失败。

GateResult 至少返回 allowed、reason_code、snapshot_revision、required_resources、estimated_finish_at。未知关键资源不能视为满足。

## 时间与承诺

统一 agenda.free_windows 汇总睡眠安排、课程、约定、在途活动、已预留时段。候选所需时间是：

去程 + 活动本体 + 去下一承诺地点的路程（或返程）+ 缓冲。

不能一律加返程又加下一承诺路程重复计算；根据目标明确选一条离场路径。交通耗时依预计出发时刻报价，起点是实际位置。

承诺分为硬约束与高优先级义务。已授权约定、不能中断的运行阶段属于硬约束；课程可以按政策请假/迟到/缺席，但必须记录明确决定，不偷偷当作普通空闲窗。

## 选择顺序

1. 恢复或处理在途操作，避免同时另起一项冲突活动。
2. 应用必要恢复与承诺政策，形成必须执行项或显式违约决定。
3. 对合法自由候选计算效用，含一个 rest/idle 候选。
4. 选择后准备并最终门控，通过才进入 running。

sleep_need 是连续状态输入；是否立即睡眠由政策和当前可停靠点决定。生病不等于所有非睡眠活动永久禁止。

## 效用与 softmax

首版效用可使用：需要缓解、兴趣匹配、意图价值、截止紧迫度、承诺价值，减去时间成本、资源成本和近期重复。各项先归一化并输出分项，权重放在版本化策略配置，不散落到模板和状态模块。

~~~text
u_i = weighted_features(candidate_i, snapshot, profile)
p_i = exp((u_i - max(u))/T) / sum_j exp((u_j - max(u))/T)
~~~

T>0 为温度；T=0 明确定义为最高分选择并采用稳定并列规则。温度只改变合法自由候选的探索程度，不能让预算不足或缺权限的活动被抽中。

同一兴趣不要同时乘触发概率、效用和结果奖励。触发表示机会，效用表示当前偏好。候选选择种子、分项和策略版本留在诊断轨迹，不向模型暴露不必要的内部调试数值。

## 每日规划器

首版按规则放入固定承诺、必要生活需求和少量目标，留下空闲与缓冲。作业可切成小块；已接近截止的任务优先占用可行窗口。不要默认把全部时间排满。

规划结果是 proposed blocks，必须经门控转成实际活动。LLM 可辅助在有限目标间建议，不得编造余额、课程、地点或直接提交成功记录。

重排只处理未执行部分；已经花钱、读过内容、走过路径不随新计划抹掉。人工调整统一走命令，保留版本与原因。

## 习惯与拖延

拖延首版可表达为高启动成本、短期舒适偏好与压力影响，不另建复杂人格模型。习惯可作为“该时段近期重复”特征。两者不会覆盖资源硬门槛。

若长期只选轻松活动，先检查效用尺度、重复惩罚和任务切块，不立即添加新的脑化学状态。生活质量通过多日模拟观察，不保证每次选择都最优。

## 验收

30 分钟空闲无法选择总需 50 分钟的出行；同目标多触发不会获得多份 softmax 权重；T=0 可确定回放；改变兴趣只改变合法自由候选偏好；课程缺席有唯一结果；改计划不删除真实进度。
