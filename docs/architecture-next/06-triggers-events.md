# 触发器与事件

依赖：[公共契约](03-shared-contracts.md)、[活动组件](05-activity-components.md)。触发只产生候选，门控通过且实际执行之后才形成经历。

## 共同规则

一个模板内 triggers 默认 OR；同一目标的多项命中合并 reasons，不把概率相加。gating 内条件默认 AND。每个触发器有稳定 id、版本、目标生成规则、机会实例键和候选有效期。

概率 p 只对一次明确的机会判断。抽样结果或下一到期时刻持久化；读取状态、打开页面或进程重启不能重新抽签。无效/过期候选记录原因，不无限积压。

## random

rate 必须附 per，例如 2/week；内部换算成每秒风险率 λ。只计算配置允许窗口、非冷却期内的暴露时长；首版不因为余额不足而改变时钟，机会发生后可被门控拒绝。

常率时间段命中概率 p=1-exp(-λΔt)。首版推荐抽累计有效暴露时间的下一次到期阈值，而非每 tick 抽一次；跨窗口暂停暴露，进入下个窗口继续。处理频率改变不应显著改变机会分布。

同模板已有候选/在途实例时合并或跳过机会，不创建并行副本；计数记录“机会”和“实际开始”分别统计。离线期间不补造一大串自由随机活动。

## time_window 与 calendar

time_window 生成由本地日期、时区、窗口编号确定的机会。默认每窗口只判定一次；窗口结束后候选过期。跨午夜窗口按开始日期归属，夏令时的不存在/重复时间必须有明确策略并写测试。

calendar 面向真实日历实例：课次、考试、生日等，支持 lead_s。重复规则先展开为稳定实例；调课通过同一实例 revision 更新，取消旧版本的候选和延迟任务。多个提前提醒是明确配置的不同机会，而非窗口轮询的副产物。

生日提前一周是未来生日实例的 lead time，不是生日发生后设置负 delay。

## state 与 env

默认 mode=enter，在已知 false→true 时判断一次。加载时从 unknown 变为 true 不默认算“刚跨阈值”；如果需要启动时判断，配置 fire_on_initial 并将该机会持久化。退出阈值可与进入阈值不同，防止边界抖动。

若需“压力持续高时，每小时有机会吃零食”，显式 mode=hazard 和 rate/per，不重复解释 p。条件必须声明所读状态/环境键。

天气包含 observed_at、有效范围和时效。过期/失败返回 unknown；unknown 不等于晴天。复杂 env 判断注册为小型纯函数，不直接在表达式中发网络请求。

## feed 与 intent

feed 按 source_id、item_id 和内容版本去重；匹配标签前先过滤权限。相同材料刷新不重复触发；实质更新是否算新机会由提供方契约声明。

intent 表示尚未满足的目标，如“本月想看这个展”。可执行时产生候选；活动成功后由意图拥有者关闭，部分完成时按目标规则累计。保存 target、created_at、deadline、status、source_refs。意图满足是结果，不应再作为启动同一目标的循环条件。

## chain 与 delay

chain 消费已提交事件，按 event_id、consumer_id、trigger_id 去重。订阅具体类型及条件，例如 parcel.arrived 且未领取。只保留接收端声明，删除双重 parent.followups 语义。

delay 是对未来任务的预约，due_at 不得早于原因事件的有效时间。队列保存因果事件、目标版本和撤销键；宿主重启后继续等待。若恢复时已经过期，按业务处理：快递仍可领取，旧“出发去已结束课程”应过期。

禁止 commute.after="*"。事件链不能把未发生的后续直接写成完成经历；每次链式活动仍过门控和选择。先检查直接循环；长链可设每次因果链的合理生成上限并在达到上限时输出诊断，不能静默无限派生。

## 频率与冷却

cooldown 默认从实际进入 running 时起算；准备失败走单独退避。max_per_week 统计当地日历周内实际开始次数，实例重复恢复不重复计数。首版已有 pending/active 实例的同目标触发合并。

## 验收

1. 同一事件投递两次只生成一个取件候选。
2. 改 tick 步长后固定时间内 random 分布近似一致，重启不重抽机会。
3. 高压力保持一小时，enter 只命中一次；跌出再进入才有新机会。
4. 旧课次 revision 的提醒失效；负延迟配置拒绝。
5. 缺天气不会触发“晴天散步”；离线恢复不集中补跑已过期活动。

数学关系参考 [Stan 生存模型](https://mc-stan.org/docs/stan-users-guide/survival.html)。附件 rate 的“每周”语义来自 activities.yaml 的字段注释。
