# 总体架构

阅读依赖：[总入口](README.md)。下一篇：[插件边界](02-plugin-boundaries.md)。

## 目标与首版范围

让活动库可以持续扩充，而内核与主插件不随每种活动一起膨胀。生活应包含连续状态、时间承诺、地点、资源与可接续产物；具体经历可以由现实材料支撑，也可以来自清楚标识的规则模拟。

首版采用同进程调用、独立生活 SQLite、一个生活调度器。组件是 Python 包与 YAML 模板，不要求各自安装为 AstrBot 插件，不引入独立服务、远程消息队列或通用工作流引擎。

## 五个层次

| 层次 | 职责 | 不承担 |
|---|---|---|
| 内核 | 时钟、统一推进、候选调度、生命周期、事件投递、持久化协调 | 具体课程内容、某种病的规则、某个地图供应商格式 |
| 领域模块 | 拥有领域事实及更新规则，提供查询、报价、命令 | 任意修改别的模块状态 |
| 活动组件 | 模板、执行器与活动专属规则，产生进度、回执和产物 | 直接访问主插件数据库或绕过通用授权 |
| 配置包 | 身份、生活规则、课程、校园、活动选择与参数 | 任意可执行 Python、账号凭据、私人记忆 |
| 适配器 | 宿主能力、外部路线、天气、内容等协议转换 | 代替领域模块决定活动是否完成 |

建议领域模块：sleep、nutrition、energy、affect、stress、health、academics、economy、geo、environment。初期允许若干模块放在同一文件或子包，不为目录整齐拆出大量空类。

## 依赖方向

活动组件 → 内核契约及领域接口；领域模块 → 公共数据类型与显式只读输入；外部调用 → 受限适配器。主插件通过生活服务读事实、提交命令，并消费已提交的生活事件。

模块之间使用注册的查询/命令协议，不访问彼此内部对象或表。最重要的耦合只有：

- 学业负荷 → 压力；压力、睡眠与活动负荷 → 精力或健康模型。
- 时间承诺、路线、钱包 → 门控；状态与兴趣快照 → 候选效用。
- 执行结果 → 领域结算；生活事件 → 主插件记忆、兴趣、日记与分享候选。

双向状态影响使用同一旧快照计算下一状态，不能互相调用 update 形成递归。

## 建议代码组织

以下是职责组织，不要求立即移动现有全部文件。

~~~text
good_life/
  kernel/       clock, registry, scheduler, lifecycle, events
  contracts/    immutable records, commands, receipts
  modules/      sleep, affect, academics, economy, geo...
  activities/   executors + built-in templates
  adapters/     companion_host, routes, weather, materials
  profiles/     core, student, authored_world
  storage/      repositories, migrations
  web/          read models, commands, diagnostics
~~~

复用仓库中已经存在的注册、LifeRuntime、LifeStorage、交接与恢复机制。目录重排本身不是交付成果；以一个活动是否能正确执行为单位提交。

## 第一条完整路径

买饮料：允许时段内产生机会 → 根据空闲窗和钱初筛 → 选择附近店铺 → 报路线与价格 → 最终门控 → 锁定实例、时间和预算 → 按阶段移动与消费 → 写实际支出、位置和效果 → 保存当次结果 → 主插件按需读取。

该路径必须既支持正常完成，也支持余额不足、关门、取消与重启。用它验证通用契约后再增加课程、出行等复杂流程。

## 明确暂缓

完整神经递质网络、每个 NPC 一个 LLM Agent、全校教务平台、精确全校排名、多币种金融、无限并发伴随活动、图形流程编辑器、任意用户脚本语言。新增需求只有在当前模型无法解释具体行为时再扩展。

## 完成判据

新增一个使用现有执行器的活动，只需模板、输入绑定和样例验证；不改内核，不增加主插件专属活动分支。替换地图供应商不改变活动生命周期。停用某领域后，依赖它的活动准确显示不可用原因。
