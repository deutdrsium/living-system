# 插件边界与主插件能力

阅读依赖：[总体架构](01-overview.md)、[公共契约](03-shared-contracts.md)。具体抽取路线见 [执行与感想](14-execution-impressions.md)。

## 已确定的长期边界

世界插件不只触发事件。它拥有活动业务过程：准备什么、执行哪一步、何时完成、进度如何保存、产生了什么当次产物。主插件提供人格及基础能力，并决定经历如何进入长期自我理解与对外关系。

| 对象或行为 | 唯一拥有者 |
|---|---|
| 日程、活动实例、阅读/浏览进度、课堂参与、出行进度 | 生活插件 |
| 睡眠、饥饿、精力、情绪、压力、健康及现有其他状态 | 生活插件 |
| 当次读书笔记、即时感想、作业块、路线/消费回执 | 生活插件的活动账本或产物仓库 |
| 人格、关系、长期记忆、兴趣成长、自我反思 | 主插件 |
| 日记、梦境、换装、聊天、主动联系 | 主插件 |
| 身份、授权、通用来源资产、模型网关、平台账号、基础审计 | 主插件 |
| 钱包流水、课程资料结构、地点与模拟世界事实 | 对应生活领域模块 |

“生活持有产物”指业务记录与生命周期。文件字节或通用来源可以仍由主插件资产服务托管；生活只保存资产引用、来源和权限，不复制一份不受撤回控制的正文。

## 当次感想与长期理解

当次感想回答“这次实际读到/做了什么，我怎样反应”，绑定具体 activity_id、材料范围、人格上下文版本和生成任务回执。世界侧组织生成与保存。

长期反思回答“这些经历放在一起说明什么，我的兴趣或看法怎样改变”，由主插件运行。它读取已完成或部分完成的记录，不把计划当成经历。

例如伦理学阅读：生活侧读取授权片段、保存读到的位置和一条疑问；主插件之后决定是否记住这条疑问、是否更新兴趣、是否在聊天中提及。长期记忆收录失败不应把已经读完的活动改成失败。

## 主插件能力端口

以下是目标语义，不是声称当前已有这些同名方法。A0 已在 [03 契约 v1](03-shared-contracts.md) 和 `good_life/contracts/ports.py:CompanionHostPorts` 冻结精确请求/返回签名；九个目标方法均为 async，须单独能力协商，不替换现有同步注册接口：

| 能力 | 输入与输出边界 |
|---|---|
| resolve_authority | 原始会话/角色/行为 → 已核验执行范围；不能由 YAML 自报身份 |
| get_persona_context | 角色、用途、允许的材料 → 有版本的受限人格/兴趣/记忆上下文 |
| read_material | source_ref、范围、用途 → 授权内容、版本、来源与受众 |
| run_model_task / inspect_task | 稳定任务 id、任务类型、输入、预算 → 持久任务状态、结果引用和用量 |
| execute_platform_action / inspect_action | 已授权动作、稳定操作 id → 确认、拒绝或 unknown |
| publish_asset | 当次产物及来源关系 → 受权限管理的资产引用 |
| accept_life_event | 已提交且可核验的事件 → 宿主持久收件回执 |

v2 batch 1 已由 coordinator 批准并在 [03](03-shared-contracts.md) / `contracts/v2.py` 冻结。reconcile_life_command、abort_own_prepared_command、start_authorized_intent、inspect_authorized_intent 归独立本地协调端口，按能力组显式请求，默认关闭；v1 的两种 local action 继续兼容。模型 v2 的执行状态与 ResultAccess 分离，deadline/absence 为目标声明，当前宿主不声明模型 v2 能力。真实平台动作/新材料工具资产/chain-delay（V2-04/05/06）延至 A7。配对和调用方见 [迁移映射](contract-v2-migration.md)。

人格上下文不等于把完整内部 app、数据库连接、整套私密记忆传给生活侧。模型网关允许世界侧提供活动任务的结构化输入和模板版本；宿主保留权限、预算、执行监督与来源约束。

## 当前桥接与最终归属

现有 reading_scheduler 调用宿主 execute_reading；宿主再调用 RoleReader。这可以作为兼容桥，但不能据此认定业务已彻底解耦。

保留桥接期间，明确每个活动的 execution_owner。同一实例只走一条执行路径。先抽离世界侧阅读编排，再让宿主只保留授权材料与通用模型任务能力。新活动直接采用目标边界，避免主插件继续增加 attend_class、museum_visit 等专属执行分支。

当前 companion.life.v1 的同步提供方处理器仍保持同步；现有 async 宿主能力与未来异步任务端口单独管理。不要把 awaitable 塞进现有同步注册接口。新增语义必须协商能力与版本，不能静默改变 v1 的参数含义。

## 为什么暂不新增第三个插件

独立“人格引擎”或“工具平台”插件会增加部署、兼容和生命周期成本，目前没有独立复用需求。先在两个插件内部形成模块边界即可。保留同进程能力调用不妨碍活动模块化。

## 验收

世界侧新增一个普通活动不改宿主活动类型分支；同一阅读产物只保存一次；宿主记忆消费者重试不再次执行阅读；主插件断开时活动明确等待或暂停；未知模型/平台结果不会因切换执行器而重新发送。
