# 状态黑板与数值推进

依赖：[公共契约](03-shared-contracts.md)。具体模型见 [身体](09-body-models.md)、[情绪健康](10-affect-health.md)。

## 单一拥有者

每个 key 只归一个模块。睡眠拥有 S、C 相位及睡眠记录；营养拥有饥饿；精力拥有 energy；情绪拥有 mood；压力拥有短期/慢性压力；健康拥有病程。钱包、课次与位置虽然可投影到黑板，但不接受通用 state.set 修改。

blackboard 是受限快照读取接口；领域模块通过受校验命令提交自己的结果。活动的 effects 由目标拥有者解释。例如 meal.consumed 交给营养模块，不能由每个吃饭模板随意写 hunger=-50。

元数据按 03。expose_to_llm 与 buckets 用于生成可读分档，不改变内部事实；分档先固定边界和版本，防止数字轻微波动造成描述反复跳变。

## 推进契约

模块提供逻辑能力：

- describe：状态、依赖、参数版本与支持的更新方式。
- advance(from, to, old_snapshot, known_inputs)：返回本模块下一状态，不直接修改其他模块。
- apply_effect(effect, current)：核验事件、有效时间与重复编号，返回本域变更。
- project：输出对其他模块或聊天可见的派生指标。

内核以同一时刻快照计算所有模块增量，然后统一提交。本地事务中记录时钟推进点和效果去重，不能状态更新成功、last_advanced_at 未保存，导致重启再积分一次。

## 时间步与事件边界

先找到睡眠开始/结束、活动阶段、进食、病程变更和参数变更等已知边界，再逐段推进。区间内常参数且有解析形式时直接计算；耦合不可解析时使用固定小步并检验步长敏感性。

不要让模块各自使用 wall clock；不要每次读状态都随机推进。界面/聊天读取只能取快照，必要时请求内核统一推进到现在。

随机状态使用独立于 UI/候选的随机流。记录种子、流状态、模型版本与边界；同样轨迹可以回放。不同切段下无需承诺随机路径逐点相同，但分布应稳定，不能因浏览页面次数而改变情绪。

## 外部刺激与耦合

事件效果可为瞬时冲击、某段时间的负荷或持续输入。所有效果附 effect_id、effective_at、来源和实例。迟到事件不能直接倒改已发布历史；必要历史校正另走带版本的修订命令并重算受影响区间。

先保留少量显式耦合：

- 睡眠不足、活动负荷 → 精力恢复/消耗。
- 学业剩余工作与可行时间 → 压力目标。
- 压力、近期睡眠与事件刺激 → 情绪模型输入。
- 睡眠债、慢性压力、配置的环境暴露 → 模拟健康风险。

禁止通过“情绪变化事件 → 压力变化事件 → 情绪变化事件”形成无休止即时循环。连续相互影响在统一推进中处理。

## 初值与校准

迁移阶段保留旧字段、文字状态、尺度、公式、提示词与当前值。切换新模型需显式 mapping：来源字段、转换方式、无法映射的处理、保留历史与回退版本。

初值来自迁移、角色预设或明确人工设置；不能上线时全部重置成 0.5。参数分为通用模型默认值和角色覆盖；数量以能解释行为为限。

先用基线场景观察睡眠、精力和压力的范围与时间尺度，再引入更多耦合。不得把文献模型名称当成已经校准的证明。

## 停用和人工修订

停用模块时 values 变为 unavailable，相关活动按依赖暂停/禁用；原数据保留。角色切换和模块版本升级不覆盖其他角色数据。

人工调状态需验证范围、权限、预期版本和有效时刻，保存修订理由；余额、成绩、位置走对应领域命令。禁用 LLM 暴露不代表删除状态。

## 验收

相同事件不重复加效果；两个模块不能注册同一 owns；读页面不推进随机状态；跨睡眠边界推进结果正确；较小步长不会大幅改变基线轨迹；重启不重复积分；缺依赖明确 unavailable。
