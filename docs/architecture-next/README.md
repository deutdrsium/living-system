# 生活插件整体架构规划

版本：设计基线 v1，2026-11-16。适用插件：astrbot_plugin_good_life「我会去好好生活」及其主插件 astrbot_plugin_private_companion。

本规划供后续实现模型按任务阅读和实施。目标是让生活插件拥有活动的完整过程、数值状态和当次产物，同时复用主插件的人格、来源、权限、模型和平台能力。主插件继续负责长期记忆、兴趣成长、反思、日记与对外表达。先保持两个 AstrBot 插件，内部按模块与组件组织，不新增第三个运行服务。

这是一份目标架构，不能作为功能已经实现、迁移已经完成或获准部署的证明。历史迁移约束仍见 [第一阶段计划](../phase-1-plan.md)，实际进度需重新核查 [实施状态](../implementation-status.md) 和代码。本文书写时读取的 HEAD 为 469267b78e3221e9fdb35b0f8cf2fb34fbc47de2；工作区还有页面迁移中的未提交改动，因此该 SHA 不是本规划所依据代码的完整快照。

## 使用方法

1. 先读 01、02、03，确定边界、共同术语和接口约定。
2. 认领一个任务包，再读对应子系统、18 的依赖顺序和 19 的验收场景。
3. 开始改代码前检查当前实现，复用已有生活库、提供方注册、任务审计和交接协议。
4. 每次交付一个可运行的完整路径，并给出相应验证；不要一次实现整套规划。
5. 如果实现必须改变本文的规范字段或状态语义，同时修改公共契约和受影响文档，不能在不同模块中各自解释。

“必须”是跨模块不变量；“首版”是当前推荐实施范围；“以后”不属于首版任务。文中的接口和表名除明确标为现有之外均为设计名称，允许映射现有实现，但含义与归属必须一致。示例学校、金额、课程、参数均不代表真实资料。

给其他模型使用时，提供本目录和相关仓库上下文即可。打包版包含本目录全部 20 篇文档；指向父目录迁移说明及插件代码的链接需要放回原仓库才能打开，它们不是可用规划文档替代的实施证据。

已确定：两个插件的长期边界、活动组件接入、数值维护状态、学业/经济/地理方向，以及保持当前迁移行为。本文进一步固定的生命周期、字段名、首批模板和最小算法是 v1 实施默认值；实现发现具体矛盾时先更新共同契约，不自行在一个模块中另起解释。具体学校、课表、地图节点、材料源、生活费和数值参数由配置包提供，不能在通用代码里臆造。完整神经递质、全校园智能体和独立第三插件明确暂缓。

## 实施模型必须保持的七条约束

- 一个角色的共享身体只有一个生活执行者；多个会话不能各自创建一副身体。
- 一个领域事实只有一个写入拥有者；黑板、聊天描述与管理页都是投影。
- 候选不是经历，计划不是完成；结果必须来自执行记录或明确的模拟规则。
- 生活侧拥有活动编排、进度和当次产物；主插件提供通用能力并拥有长期理解与表达。
- 重启可以重放幂等落库，不能把未知外部操作重新发送。
- 来源与受众权限随记录传播；撤回后不能通过感想、日记或旧缓存重新泄露。
- 第一阶段迁移保持原行为，新数值模型与新子系统分阶段启用；不要借本规划自动打开生产切换标记。
