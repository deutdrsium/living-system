# 阅读、浏览与睡眠数据迁移演练（开发中）

`tools/rehearse_activity_migration.py` 从指定的主插件运行库快照中选取角色生活活动账本，连同全部活动类型、历史版本、关联材料引用和生活操作回执迁入演练区。该账本可能包含无工作类型的普通经历或创作材料引用，保留它们可以保持统一的活动历史和回执游标；这不迁移创作功能、作品原文、日记、梦境或兴趣系统本身。

工具只读检查源库版本、完整性、外键、活动头与历史、操作完成状态和回执关联。演练导入 `staged_role_*` 表时保留所有者、活动 ID、版本、正文引用、操作 ID 和原扫描行号；不复制主插件的操作审计和来源原文。每张表按原值核对数量及摘要，同源重跑不重复导入，源数据、原有游标或演练数据发生变化时停止。

记忆摄入与成长进度使用生活操作的 SQLite 行号作为游标。演练会记录旧表行号及相关已保存游标的最大值，将新库操作序号的起点设在其后；不按目标库插入顺序重新编号。测试覆盖旧游标高于现存最大行号的情况，以及导入中断后的回滚。

活动历史的行号也用于时间线分页。`activities.v2` 演练现在保留旧历史行号，并使用不会因删除最大记录而复用旧序号的 SQLite 自增键；重复导入时检查行号与序列是否被改动。旧的 v1 演练库不会被这个版本静默覆盖，需要在新的隔离目录重做演练。

`activities.v3` 进一步保留所有生活操作回执，包括原插件删除活动及其历史后仍保留的回执。它单独统计与现存历史不关联的回执，保留原行号与操作审计引用，不据此重新创建活动；若同一活动 ID 被删除后重建，旧回执也不会被丢弃。正式切换前仍须核对这类回执的角色、操作审计与来源，不得把无法解释的异常静默当作删除。真实旧账本的删除流程和合成重建数据均已测试。

新插件的 `StagedActivityRecords` 提供内部只读查询。`tools/verify_activity_shadow.py` 对照活动、历史、回执及分页顺序。正式连接前须让主插件验证角色、会话、来源及访问权限。

主插件新增未接入生产的 `LifeLedgerReadProxy`，通过已登记的生活提供方请求上述读取，保留主插件的操作审计，并检查返回的所有者、活动 ID、版本、时间范围和分页顺序；提供方停用时明确失败，不读取旧库冒充新库。`tools/verify_activity_proxy.py` 对同一快照经代理再做逐条对照，389/986/597 条一致。该代理只实现部分读取，尚不能替换现有账本；完整会话授权、来源复核、活动写入与生命周期仍未接通。

代理现在还支持按角色和会话查询活动、读取关联材料。切换后必须使所有新活动账本写入都经过新插件，主插件只保留封存副本；若两个库各自继续生成生活回执，独立行号会冲突并可能使记忆与成长游标漏处理，因此禁止双写。

主插件开发副本增加了仅在设置回退行号下限后生效的分配方式，分别保护生活回执与活动历史；事务失败时下限回滚，删除最大行号后也不会重用。未设置下限时保持旧分配方式。`activities.v4` 导入会检查并继承这两项下限，设置新库自增序列时同时考虑已有消费者游标；测试覆盖下限高于现存记录、下限损坏和序列耗尽。旧 v3 演练库不会被 v4 覆盖。

合成数据的端到端测试已让现有记忆摄入流程经真实提供方注册和代理读取独立新库中的阅读完成回执；主插件继续执行原有来源与权限核验。测试阻止访问旧活动表，并验证停用提供方时不回退或写入经历。该测试不改变线上执行归属。

另一项合成测试让现有主动联系流程在后台线程经同一注册和代理读取新库中的阅读经历，确认只包含已读片段，不包含尚未阅读的内容。该测试也暴露并修复了新库连接最初不允许跨线程访问的问题；新库事务和读取现在共用锁。这些验证不发送真实消息，也不代表线上执行归属已经切换。

身体时钟按角色读取私人工作活动的调用已通过账本边界；测试检查睡眠在同一角色的不同私人窗口共享，同时维持状态、工作类型和时间顺序。影子对照覆盖隔离快照中的全部角色及睡眠、阅读、浏览筛选，不授予跨窗口阅读原文的权限。

这不是运行时切换或完整迁移：账号连接、原文来源、主插件操作审计、浏览接触/兴趣关联、日记、配置、睡眠执行、结果不明的调用、相关消费者和回退仍须逐项接通和验证。正式切换前必须停止相关写入并重做一致性备份。
