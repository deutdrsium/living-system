# 日程数据迁移演练（开发中）

`tools/rehearse_calendar_migration.py` 使用只读事务检查指定的主插件运行库快照。必须显式提供源库版本；不提供目标目录时只输出各表数量和内容摘要，不创建数据库或打印记录内容。

提供 `--stage-into` 后，工具在独立的新插件库中建立 `staged_calendar_*` 演练表，复制日程现状、历史版本及回执，保留原所有者、记录 ID、操作 ID 和 JSON，逐表核对数量与摘要。主插件的操作审计不复制；演练只核验其关联、完成状态并记录摘要。目标更改在单个事务中提交。

同一快照可幂等重跑；源记录、主插件相关操作或演练表内容变化时拒绝覆盖。版本不符、字段变化、缺失行、来源库完整性或外键错误也会拒绝。中断后的未提交演练表会回滚，可重新运行。

`tools/audit_calendar_ownership.py` 按原操作的会话、角色绑定和会话参与者核对归属。正式切换须在停写后使用一致性备份重新检查。

`tools/rehearse_calendar_migration.py` 可添加 `--adopt-legacy`：先在同一源快照内核验角色和会话，再在隔离生活库的一个事务中迁移可确认的旧角色计划及其全部历史和回执；缺少提醒会话的旧记录留在原会话。重复运行会重新核对源数据、角色绑定和迁移后的全部记录；源身份或内容变化、目标冲突、生活命令已开始或迁移中断都会停止或回滚。合成测试覆盖了多版本、原回执与中途失败。归属计划存放在受限演练库中，不能提交 Git。

`tools/verify_calendar_adoption.py HOST_SNAPSHOT LIFE_SNAPSHOT --expected-version VERSION` 在两个只读事务中重新审计角色归属，逐表对照原快照和采用后的记录，并检查生活库是否有未决命令；通过后只输出版本与摘要组成的凭证，不输出日程或角色标识。开发版宿主已有凭证对照检查，但没有为生产写入该凭证的切换流程。正式切换时须重新验证停写与跨库一致性。

新插件的内部 `StagedCalendarRecords` 支持核对记录、历史版本、回执和分页查询。提醒查询以合成数据验证。日程读取代理与主插件身份授权及角色、会话合并已在隔离测试中连接，真实插件生命周期、管理页面与提醒投递仍未接入，不能对用户开放。

这只是一次**日程数据**演练，不包括配置、阅读、浏览、睡眠、提醒投递、跨库服务调用或回退。演练表不是生产日历，新插件目前不会读取或执行它们。正式切换前须冻结相关写入并重新备份。
