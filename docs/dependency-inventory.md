# 第一阶段依赖盘点（线上源码基线）

本清单依据首个 Git 基线和数据库只读元信息整理，不包含人物资料或记录内容。数据库表被列出不代表可以直接搬迁。

## 执行与调用方

- `companion_v2/host/application.py` 同时构建日历、活动账本、阅读、浏览、配置和 `RoleLifeCoordinator`，并在宿主 tick 中推进生活与日程生成；日记计划也通过生活协调器回调。
- `role_work/life/runtime.py` 在同一执行循环中处理睡眠、读书、浏览、兴趣整理和晨间换装；重启时将结果不明的阅读与浏览暂停。阅读、浏览各自查询日历，并依靠同一个活动账本避免同时启动。
- `agenda/calendar.py` 把身份授权、来源校验、日程、提醒和操作回执放在一个主库事务中。对话工具、聊天状态、主动联系、换装、空间发布和管理页都依赖日程服务。
- `role_work/life/body_clock.py` 的活动查询已改经生活账本，仍查询主插件的聊天输入、批次和睡眠压力修正；睡眠压力配置及其写入尚未完成迁移。
- `memory/activity_receipts.py`、`proactive/events.py` 和 `storage/activity_history.py` 直接读取活动或版本表；日记材料和兴趣整理还依赖活动、来源授权与实际完成回执。这些读取需改为生活服务接口或可靠事件，不能直接访问两个数据库。
- `astrbot_host/life_api.py` 和 `role_work/life/management.py` 混合管理日记、梦境、生活设置、阅读和浏览。`role.life` 配置也同时包含日记、睡眠、阅读及浏览字段，需要按字段而非整组迁移。

## 存储迁移约束

- `calendar_history` 和 `calendar_receipts` 依赖主库 `operations`；`role_activity_revisions` 与 `role_life_operations` 也引用该表。跨 SQLite 数据库不能保留现有外键和单库原子事务。迁移前必须设计并验证操作凭证、幂等及跨插件事件的恢复机制。
- `role_artifacts` 和 `role_activity_revisions` 引用 `role_activities`；导入、核对和回退必须保持活动 ID、所有权、版本与关联关系。
- `role_activities` 和 `role_artifacts` 是共享的角色生活账本，也允许普通经历与创作材料引用。为保持单一回执序列，账本记录整体归新插件；创作、日记、梦境、兴趣功能及内容来源仍留在主插件。
- 记忆摄入和成长进度使用 `role_life_operations` 的 SQLite `rowid` 作为跨轮游标。迁出时必须保留原扫描序号，并确保新操作的序号大于原表及所有已保存游标的最大值；否则可能漏处理新活动或重复处理旧活动。
- `agenda_*` 同时承担其他提醒、投递及操作历史，不能整表视为角色生活专属数据。`role_exposure_*` 与主插件兴趣表有关，需逐项核查归属与消费者。
- 阅读原文来源和权限继续由主插件管理。当前库中另有 `reading_archive_*` 表，但不能假设它们覆盖现有 EPUB 队列、来源和全部读书笔记；还需沿实际阅读流程核对。
- 配置数据库与运行数据库分开，且 `role.life` 当前同时保存日记、作息、阅读及浏览设置；`enabled` 和时区也被多项功能共用。迁移必须按字段和实际消费者核对，不能把整组设置直接搬走。

## 可复现基线结果

- 日程编辑器：7 项通过。
- 源码基线的 `tests/test_life_workspace.cjs` 有 3 项因测试夹具滞后失败；已按现有兴趣分组、浏览偏好必填项和笔记分类更新测试，现与日程编辑器测试共 13 项通过。
- 源码基线的 `tests/test_role_life_storage.py` 旧版本升级夹具在回退至 V15 后保留了后续版本的表，导致 V68→V69 失败；已修复测试夹具对 V69–V71 的回退及重复回退，4 项测试在本机和服务器隔离环境通过。未修改生产数据库。
- `tests/test_role_body.py::RoleBodyTests::test_persona_settings_share_while_platform_presentation_stays_window_scoped` 期望配置冲突，实际返回配置无效；该断言在本次修改前的线上源码上也可复现。与睡眠读取相关的其他测试继续单独核验。
- 浏览测试中，未知互动结果的断言没有包含现有的自动推荐调用，浏览后续读测试的夹具缺少选书模型任务；两项失败均在未修改的线上源码上复现。已更新测试夹具和调用预期，仍验证未知互动只执行一次且不记录为成功。
- 原插件生活运行测试另有两处在未修改的线上源码基线 上复现：自动选书夹具缺少选书模型配置，失败后立即续读的测试没有等待既有阅读节奏。已补齐夹具，并让测试先验证节奏拒绝、再推进测试时钟重试；没有修改实际阅读节奏。
- 本机缺少 AstrBot 包，涉及 AstrBot 的测试应在隔离的服务器容器环境运行；不能据本机导入失败判断生产故障。

`tools/life_migration_preflight.py` 只读检查候选表、外键、计数、版本与数据库完整性，不读取或输出记录内容；它不是数据迁移工具，也不表示可以切换。

开发进展：记忆回执读取及扫描、成长扫描、自我反思和主动联系的活动历史查询已改为通过生活账本方法访问；账本仍位于主插件，其他直接读取和跨数据库事务尚未迁移。对原始回执、分页、记忆写入、成长后台扫描和自我反思的隔离测试已通过。

身体时钟读取私人工作活动也已通过账本接口，保留按角色跨窗口共享、筛选和排序；隔离快照中全部角色的睡眠、阅读和浏览筛选已与原记录对照。聊天休息门控、日程和状态干预、主动联系的睡眠检查也显式接收账本，提供方不可用时不回读旧活动表；它们保留原有的休息窗口和不可读处理规则。

隔离环境的休息门控和代理测试首次运行有 28 项通过、2 项在夹具等待模拟会话时超时；停止并发服务器测试后，两项分别在本机和服务器重跑通过。主动联系的睡眠门控及代理集成测试通过，未发送真实消息。

时间线的活动索引、分页和历史完整性检查已通过账本接口；模拟测试与隔离快照对照确认分页、会话范围和来源撤回。新版活动演练保留历史行号，后续新行使用不复用的自增序号；正式写入实现仍须使用并验证该序列。当前新库只是只读演练，时间线原本在主库单个读快照中合并活动、日记和成长；切到两个库后需要另行解决跨库一致快照，不能仅凭现有分页测试启用生产迁移。

正式切换前应停止相关写入，再创建一致性备份并执行预检。
