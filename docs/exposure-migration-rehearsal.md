# 浏览记录迁移演练（开发中）

`tools/rehearse_exposure_migration.py` 从指定运行库快照读取浏览会话及内容接触记录，核对源库版本、完整性、外键，并要求每条记录可对应唯一的原社交活动。会话和接触记录按原作用域、活动及内容标识复制到隔离库并逐表核对；主题、反馈、兴趣和熟悉度数据仍由主插件保留，只记录摘要以发现源数据变化。

一次浏览活动可以接触多个平台，接触记录的平台不必等于会话的初始平台；演练按原记录保留，不会把这些内容误判为不一致。主插件选择下一平台时使用会话表的 SQLite 行号顺序，演练保留原行号，并使后续序号大于原表最大行号。

本次 v71 隔离快照中，11 个会话和 260 条接触记录已按数量及摘要核对；重复演练返回未变化。演练库含私人内容，仍保存在服务器受限目录，不进入 Git。

浏览会话的当前平台和前一平台读取已收拢到接口，保留按原会话作用域和行号选择的行为；模拟测试验证另一会话不能读取记录、提供方停用时不回读旧表。`tools/verify_exposure_sessions.py` 还对新版隔离演练库中的 11 个会话逐条核对了当前与前一平台查询。浏览内容、去重、兴趣关联和写入仍未通过接口迁出。

`tools/verify_exposure_authority.py` 从原对话或任务中重建历史上下文，核对活动所有者、原会话、角色及参与者派生的作用域；服务器隔离快照的 11 个会话都匹配到一个原上下文。测试覆盖作用域调包、原上下文缺失、所有者错误和活动编号歧义。该检查只证明历史记录之间的关联，不证明当前授权仍有效；来源与权限必须在实际读取及执行时通过主插件复核。

新版 `exposures.v2` 演练把上下文校验列为必需步骤，与数据导出共用同一源库读快照，并把校验摘要写入演练清单。服务器在 `exposure-authority-rehearsal/` 重新导入并核对了 11 个会话和 260 条接触记录，重复运行返回未变化；旧版演练清单不会被新版静默覆盖。

这还不是可上线的数据切换：主题、反馈对浏览内容的跨库引用，以及使用当前身份服务复核访问授权，仍未实现。社交账号与实际互动仍由原插件管理。
