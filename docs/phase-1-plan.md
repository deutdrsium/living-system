# 「我会去好好生活」第一阶段拆分计划

> 以下保存用户批准的原计划。末尾“本轮仅制定计划”记录的是计划制定时的状态，当前进度以仓库内的演练和依赖盘点文档为准。

## 2026-11-16 修订：现有状态系统一并迁出

以下补充扩展本阶段的迁移范围；与下文原计划有范围差异时，以本节为准。本次仅修订计划，不恢复代码修改或线上迁移。

- **迁出范围**：将现有角色状态系统整体纳入新插件，包括困倦／睡眠压力、睡眠债、精力等数值，以及饥饿、健康、情绪、生理周期等已有状态；连同计算、模型维护任务、定时更新、配置、管理入口及向聊天提供状态描述的逻辑一起迁出。人格、关系、记忆与聊天仍留在主插件，主插件通过生活服务读取状态，不再维护第二套状态。
- **本阶段保持行为**：保留现有字段类型、数值尺度、更新周期、公式、模型提示词、人工设置及角色／会话共享规则。数值状态与文字状态均按原样迁移；不把文字饥饿状态强行数值化，不重置当前状态，也不借迁移调整睡眠或状态维护规则。
- **数据、接口与验收**：在既有代码、数据及调用方清单中增加状态系统，迁移当前状态、已有历史、时间戳、有效期、版本、来源引用与配置；将查询、维护与展示接入新插件归属。核对迁移前后的状态及聊天可见描述，并覆盖权限、来源撤回、重启续接、单一维护者和产生新状态后的回迁。状态页面并入“生活总览”和“作息与设置”，沿用现有风格与认证。
- **后续架构方向**：最终将分散的状态实现替换为统一状态变量系统；内核负责触发器和状态维护器，吃饭、睡眠、阅读等可执行任务作为模块通过插头接入。`StateVar` 的候选元数据采用用户提出的 `key`、`range`、`baseline`、`timescale`、`expose_to_llm`、`buckets`；它是后续设计输入，本阶段不实现统一变量内核、任务插头协议或尚不存在的任务。
- **后续模型边界**：睡眠的 C／S 双过程、生病的状态相关 hazard rate，以及新的状态演化、自然语言分档和任务效果均留待迁移完成后设计。本阶段不引入这些模型，不改变既有状态的含义。

## 1. 目标与边界

将现有生活功能从「我会永远陪着你」迁入新插件 **「我会去好好生活」**，完成本地开发、数据迁移演练及部署验收。

本阶段保持现有行为，重点改变代码、数据和执行归属。暂不开发课业、地理、经济，也不调整阅读节奏、浏览频率和睡眠规则。

| 新插件负责 | 主插件保留 |
|---|---|
| 日程生成、编辑、查询及相关提醒调度 | 人格、关系、聊天和主动联系 |
| 生活活动的启动、暂停、续接和执行记录 | 记忆、兴趣成长、反思 |
| 阅读选书、队列、进度、读书笔记 | 日记、梦境及其写作管理 |
| 自主浏览调度、执行流程及浏览记录 | 社交账号、平台连接和既有互动授权 |
| 睡眠、午休、身体时钟及相关生活状态 | 晨间换装能力、通用模型调用和消息发送 |
| 上述功能的配置和管理页面 | 统一身份、权限、来源证据及基础任务审计 |

新插件第一阶段依赖主插件。日记、梦境、兴趣整理和换装继续获得生活事件；聊天继续读取日程与生活状态。

**完成标准：迁出的功能由新插件实际执行和管理，主插件保留接口适配，不再运行第二套生活执行器。**

- 从线上获取当前实际源码作为基线，核对本地定制差异；不使用历史部署包覆盖现状。

## 3. 拆分实现与页面设计

### 插件接口与执行归属

沿用主插件现有扩展 API 的注册方式，新增带版本号的生活服务契约，第一版为 `companion.life.v1`，采用进程内调用，不引入额外服务。

接口分为三组：

- **生活服务**：查询日程与当前活动、提交日程命令、控制阅读/浏览/睡眠、读取活动和进度。
- **主插件能力**：解析角色与授权范围、获取人格和兴趣材料、调用模型与平台工具、验证来源、发送提醒、记录任务用量。
- **生活事件**：活动完成、睡眠结束、阅读或浏览产出，供日记、梦境、兴趣成长和换装使用。

调用保留现有角色、会话、来源、操作编号和版本校验；不向新插件暴露主插件数据库连接或完整内部应用对象。

新插件持有唯一生活调度器。主插件相关调用统一转向接口，旧页面 API 对迁出操作做兼容转发，日记和梦境操作仍由主插件处理。

插件加载顺序不影响绑定；主插件缺失或版本不兼容时，新插件显示原因并暂停执行。任一插件重载时撤销旧绑定，待重新握手后恢复，防止重复计时器和重复任务。迁移完成后，新插件停用不会自动恢复旧执行器。

### 数据与跨插件连接

- 新插件使用独立数据目录和 SQLite 数据库，拥有日程、生活活动、阅读进度、读书笔记、浏览记录、睡眠状态及对应配置。
- 角色身份、权限、通用来源资产、平台凭据和基础任务审计保留在原归属，通过接口访问；已有书籍来源不复制成第二套。
- 保留角色和会话标识、活动编号、版本号、来源引用及去重记录。共享表按业务归属导出，不直接整体搬走。
- 日记与兴趣整理通过生活接口读取已完成经历；来源撤回后继续遵守原有隐藏与访问限制。
- 生活事件采用持久化待处理记录，接收方按事件编号去重，避免重启后重复生成梦境、重复整理兴趣或重复换装。
- 既有模型任务和结果不明的社交操作保留原审计记录，不因拆分自动重试。

### UI/UX

新插件提供独立管理页，沿用主插件现有颜色、字体、卡片、表单、导航及移动端布局。复用必要组件和样式，不复制整套陪伴小屋。

首期导航固定为：

- **生活总览**：当前活动、今日安排、睡眠状态。
- **日程**：日历、安排编辑、相关提醒。
- **阅读**：书库入口、导入、进度、笔记和续读。
- **浏览**：浏览记录、当前状态和浏览偏好。
- **作息与设置**：睡眠、生活配置及依赖连接状态。

原主插件入口保留跳转，原“日记与生活”页面保留日记、梦境，并链接新生活页面；新页面可返回原日记页面。社交账号管理仍链接主插件，避免维护两份配置。

新插件静态资源和 API 使用自己的路径；沿用 Pocket ID 与 AstrBot 身份校验，不通过公开接口绕开认证。本期不放置尚未实现的课业、地理和经济空页面。

## 4. 数据迁移、上线与回退

按以下顺序实施，每一步通过后再进入下一步：

1. **依赖盘点与基线测试**：形成迁出代码、数据、配置和调用方清单，覆盖日程、对话状态、日记材料、兴趣、换装、管理页及后台生命周期。
2. **本地拆分**：先建立接口和插件生命周期，再依次迁出日程、阅读、浏览、睡眠，最后调整页面与旧入口。
3. **迁移演练**：使用生产数据的一致性备份，在隔离环境执行预检、导出、导入、核对及回退；演练禁止发送真实消息或执行真实社交互动。
4. **线上切换**：先备份源码、配置、数据库和相关资产，停止接收新的生活任务，等待在途调用结束；不能确认结果的活动保留暂停或未知状态。保存睡眠起止时间，不等待整段睡眠结束。
5. **导入并启用**：迁移工具按角色和会话核对记录数量、关键字段、来源引用、阅读位置和配置；成功后写入执行归属标记，再启用新插件。旧数据保留为封存副本，旧执行路径停止。
6. **线上验收与发布记录**：验证实际页面和执行链路，记录发布提交号、备份位置、迁移结果及尚未观察到的自然活动。

迁移工具支持预检、试运行和幂等重跑，遇到版本变化或数据冲突时停止切换，不静默覆盖。

回退分两种：

- 新插件尚未产生新数据：恢复配套旧代码与备份。
- 已产生新数据：先停止新执行器，将切换后的生活数据和去重记录回迁并核对，再恢复旧执行器；不能直接恢复旧快照丢弃新增记录。

## 5. 验收与交付

**功能与数据**

- 日程生成、编辑、重复安排、约定和提醒保持原有行为。
- EPUB 导入、选书、进度、笔记、暂停及已授权续读保持有效，不跳过未读片段。
- 浏览保留实际工具回执和互动去重，未知结果不重复执行。
- 睡眠、午休和身体时钟连续；梦境、日记、兴趣与晨间换装连接正常。
- 多角色、多会话不串数据；聊天能准确读取生活状态。
- 配置、来源撤回、权限拒绝和 Token 统计不因拆分失效。

**生命周期与迁移**

- 测试两种加载顺序、停用、重载、版本不兼容和进程重启。
- 确认同一角色只有一个生活执行者，提醒和后续处理不重复。
- 覆盖空数据、已有数据、迁移中断、重复迁移，以及产生新数据后的回退。

**页面与线上**

- 使用浏览器标签页控制或浏览器调试验证，不使用整个电脑的 Computer Use。
- 在 Pocket ID 登录环境检查新旧入口、嵌套 iframe、脚本、样式、后台读取和配置保存。
- 验证匿名访问及未授权写入仍被拒绝。
- 进行受控运行验证，不能把模拟记录当作角色的经历，也不能把尚未发生的自然活动标记为已验收。

交付包括两个配套插件安装包、完整 Git 历史、计划与接口说明、迁移及回退工具、测试结果和上线验收记录。

本轮仅制定计划，尚未创建仓库、修改源码或操作线上系统。
