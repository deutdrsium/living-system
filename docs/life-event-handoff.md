# 生活事件交接基础（开发中）

新插件的 `LifeStorage` 使用独立 SQLite 文件。生活记录及相应事件必须在同一个 `transaction()` 中提交；事件以稳定 ID、角色所有者、原始上下文、类型、时间、内容和消费者列表绑定。重复提交相同事件返回原序号，若同一 ID 对应不同内容则拒绝。每个消费者有独立的待确认状态。

主插件的 `consume_once` 校验事件摘要、角色所有者和原始上下文，并要求调用方提供主插件的授权检查。它在主插件数据库的同一事务中预留操作、运行同步本地效果并完成回执；再次投递相同事件会检查已有回执，不重复应用。只有主插件成功提交后，新插件才能确认相应消费者。主插件提交后、新插件确认前中断时可安全重投；事务中失败则回滚效果和回执。

授权回调必须明确返回成功且值为 `True`；同步效果回调必须返回 `None`。返回失败对象、`False` 或异步结果时事务回滚，不能把未执行的效果记为成功。

独立生活库允许后台工作线程访问，并将同一连接的事务与记录读取串行化；写入事件和确认投递时还要验证当前线程拥有事务。测试覆盖并发写入、跨线程错误写入及后台读取。使用库对象创建读取器才能共享锁；原始 SQLite 连接只用于单线程离线核对。

这个机制只保证在主插件同一数据库事务内完成的本地效果去重，不能使模型调用、消息发送或其他外部操作变成事务。实际消费者应在事务内写入其既有任务或待处理记录，由各自的执行器根据原有规则处理；不能直接在事件回调里调用外部服务。

本阶段只是独立可测的存储和交接基础，尚未接入日记、梦境、兴趣、换装或实际生活执行器；不能作为生产切换的依据。来源撤回、原始权限和业务层回执检查仍需在各消费者接入时完成。
